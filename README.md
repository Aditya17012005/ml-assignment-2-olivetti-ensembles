## Reproduction

Use Python **3.14.3** (the exact executed version is also recorded in
`results/environment.json`; that log takes precedence). From the repository root:

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m unittest discover -s tests -v
.venv\Scripts\python -u -m src.experiment --config configs/experiment.json --workers 8 2>&1 | Tee-Object -FilePath experiment.log
.venv\Scripts\python -m src.check_bootstrap_equivalence
.venv\Scripts\python -m src.figures
.venv\Scripts\python -m src.report
.venv\Scripts\python -m src.audit
```

On Linux/macOS replace `.venv\Scripts\python` with `.venv/bin/python` and use
`2>&1 | tee experiment.log` for the experiment command. No shell activation is
required. The first experiment run downloads Olivetti via scikit-learn.

To regenerate only the figures and PDF from committed final logs:

```powershell
python -m src.figures
python -m src.report
python -m src.audit
```

The final report is `output/pdf/ML_Assignment_2_Report.pdf`. It is an eight-page
CVPR-style document with US Letter paper, Times body text at 10 points, 6.875-inch

hash is the current `git rev-parse HEAD`. The generated PDF is deliberately
untracked so embedding its source commit does not create a self-referential

## Experimental contract

- `fetch_olivetti_faces(shuffle=False)`, all 4096 raw pixels; no transformations,
  normalization beyond the dataset's original representation, feature selection,
  or dimensionality reduction.
- `default_rng(26002)` is used only for the split: identities 0 through 39 in
  order, one permutation of their ten indices, then first 6 train, next 2
  validation, last 2 test. `data/split.json` is immutable and includes a dataset
  SHA-256. All subsequent work reuses these indices.
- Clean training only. The second test set differs solely at `[24:40,24:40]`,
  which is zeroed, including boundary rows/columns 24 and 39.
- Every tree considers all features and uses sklearn's default Gini criterion.
  Only `DecisionTreeClassifier` is imported; no ensemble library is used.
- Bagging draws 240 indices with replacement per tree and uses hard votes.
  The size grid consists of prefixes of one 200-tree ensemble. OOB accuracy
  excludes uncovered training examples; coverage is reported for every size.
- SAMME fits weighted CART, uses `alpha=log((1-error)/error)+log(K-1)`, and
  multiplies misclassified sample weights by `exp(alpha)` before normalizing.
  The update is computed in log space for numerical stability. The toy and full
  experiments call the identical update function.
- A learner with error at least `1-1/K` (within `1e-14`) is rejected and fitting
  stops. An invalid first learner raises an error. A perfect learner gets the
  finite alpha for machine epsilon and stops fitting. Accepted-round counts
  and stopping reasons are logged.
- Selection uses clean validation accuracy only, with first grid entry breaking
  ties: depth `[2,4,8,16,None]`, leaf `[1,2,4]`; bag sizes ascending; boosting
  depths ascending then rounds ascending. Test results do not enter selection.
- Confidence is a descriptive winning vote/probability, **not calibrated**.
  Single trees use leaf probability, bagging hard-vote fraction, and SAMME
  alpha-weighted vote divided by total alpha. Ties choose the lowest label.
- Q1 disagreement and vote margins use the clean validation set. Q3
  disagreement uses the fixed clean test set. For B=1, pairwise disagreement
  is undefined (blank CSV field), not zero.
- Matched training times are cumulative sequential fit times for prefixes of
  the trained ensembles, excluding evaluation and dataset loading. They are
  single observed timings, not benchmark averages, and vary by hardware/load.
- The grid timing runs materialize literal bootstrap rows. For the large refit
  experiment, duplicate (pixel vector, label) rows are represented by integer
  sample weights when minimum leaf size is 1. Each tree still draws 240 indices;
  only their representation is compressed. All 4096 pixel columns are retained.
  Gini class counts, admissible splits and thresholds are identical. This shortcut
  is disabled for larger minimum leaves, where unique-row counts could change
  split constraints. `src.check_bootstrap_equivalence` checks 27 actual face
  trees for identical split features, thresholds and all-400-face probabilities;
  results are saved in `results/bootstrap_equivalence.json`.
- `SeedSequence([26002, ...])` creates deterministic training/refit streams.
  Tree grid uses stream 1, bagging 2, boosting 3/depth, refit sampling 4, and
  refit tree/bag/boost streams 30/31/32 plus repetition. Refit randomness thus
  measures both sample resampling and learner randomness. Matched depths use
  identical bootstrap and tree seeds. See `stream` in `src/experiment.py`.
- The 30 refit training sets draw six times within each identity from its
  original six training faces. Saved indices are relative to the original
  240-row training set. Validation and test faces never enter training.
- For Q3, the single-tree class vector is its leaf distribution; bagging and
  boosting vectors follow the confidence definitions above. Variance divides
  by R=30 as prescribed; accuracy SD uses the sample denominator R-1=29.
  Bias squared plus variance is checked against mean multiclass Brier error.
  Leaf occupancy counts training rows, including replicated rows in a bootstrap;
  it is not a count of distinct original photographs.
- If validation selects an unrestricted tree, no strictly deeper maximum depth
  exists. We report depths 2, 16, None and a depth-64 saturation control.
  Depth-64 fits are reused from unrestricted fits only when **every realized
  tree depth is strictly below 64**, with identical randomness. Otherwise they
  are fit explicitly. This establishes equality without pretending that the
  control creates additional depth. Depth 16 provides a useful intermediate
  comparison; it is never used to retune the final model.

All face labels in figures and logs are zero-based (0-39). Case studies use the
first matching test example in the saved split, not a search over alternative
splits. Complete nonzero vote counts are stored, including losing classes.
The heavy training face maximizes its post-update weight over selected rounds.
Robustness cases are descriptive; they do not prove which training image caused
a test error.

Use `--resume-refits` only to resume an interrupted run with unchanged source,
configuration and split. Full reproduction should omit that flag. Floating-point
results are expected to match with the pinned environment; elapsed times and
platform metadata naturally differ.

The recorded run completed the grid and four literal-bootstrap refits, then
resumed the remaining 26 with the validated count representation and eight
workers. The first four equivalent outputs were retained. To resume only the
refit phase after a runtime interruption, without rerunning grids:

```powershell
python -u -m src.experiment --config configs/experiment.json --refits-only --resume-refits --workers 8
```

This requires the saved selections, final grid logs and split from the same
configuration. A fresh full reproduction uses the single command above and
the count representation for all 30 refits. If refits are still pending, the
report script writes an explicitly marked six-page draft under a distinct name.
